# `.opencode` 修复复核报告

## 1. 复核范围与方法

复核依据为 `/修复方案.md` 的 F1~F13 与第 5 节 R1~R8。按方案第 1 节约定，复盘 4.4（Windows 适配）、4.5「全局技能权威目录没有配置支撑」及 `opencode.jsonc` 属排除项，不计入缺陷。

复核对象：3 个 agent（`.opencode/agent/`）、8 份 `SKILL.md`、7 份 `references/` 补充件、13 个 Python 脚本、`tool/show_markdown.ts`、`opencode.jsonc`、工作区根的 `.selftest.sh`（不在 `.opencode/` 内），并交叉参考修复方留下的 `file/_suite/reports/` 回归报告。

复核方式：逐项静态核对实现与文档口径；对可判定项做独立动态验证；用现有回归报告印证 phase 步骤集合与静默漏验判定。动态验证均在本机以 `python.exe` 执行绝对路径命令，未改动任何产物。

排除项确认：`opencode.jsonc` 仍只有 `$schema` / `default_agent` / `experimental.todos`；`show_markdown.ts:17` 保留 `startsWith("/")`；`.setup_demo.sh` 未创建。三者与方案约束一致。

结论：13 项中 **7 项已修复、6 项部分修复**。五个核心问题对应的阻断性缺陷（强制自愈回写、相对路径反复试错、机验范围扩大、生成者零机器自检、报告防伪不可重放）均已消除；残留集中在配置内外的引用边界、skill 与 agent 的层级边界、工件命名，以及提示词中混入的过程性备注。逐条处置意见见第 4、5 节。

## 5. 提示词过程性备注残留清单

这类备注**不应出现在提示词中**。判定标准：删掉后不改变任何一条可执行规则的文本，都属于过程性备注。具体理由：

- 只记录维护过程、历史口径或未来动作，不产生当前执行约束，占用上下文并稀释规则密度。
- 「此后新增一行待裁决 Pn」「须逐一核对」「质检/生成端不得先行预判」是给维护者的元指令，会被模型当作执行规则，甚至把维护动作带进生成与质检。
- 内含已废止口径（多挂靠回潮、附件 5、发散-收敛）与配置结构路径（`.opencode/agent/...`），既有诱导旧口径回潮的风险，也与 Q03、Q04 的配置边界要求冲突。
- 版本日期、缺陷单流程、最小重放复验记录属于维护台账，应留在配置外的维护文档；配置内不得引用配置外文件。

检索范围为 `.opencode/agent/*.md` 与 `.opencode/skills/**/*.md`。最集中在 `补充-TP切分与命名判别.md`（§三裁例通告表及表后三段），其余散落在 3 份补充件的身份声明、若干 `SKILL.md` 的废止说明、agent frontmatter 注释与正文括号备注。

1. 修复方案必修范围内的阻断性缺陷已全部消除：`check.py` 不再强制自愈、路径全链绝对化并按 phase 严格裁剪、生成者交稿有只读预检、QA 报告防伪可重放、`.selftest.sh` 四项自检实测全绿。独立动态验证的 8 组结果均与方案预期一致。
