# RMPF 需求管理平台 — 后端设计文档

> 子系统编码：`SUBSYS_RMPF_BS`（简码 `RPBS`）
> 根 POM artifactId：`dapr-apbm-subsys`（由 APBM 基础管理子系统演进而来，两者共存于同一 Spring 容器）
> 技术栈：Spring Boot 2.4.4 + MyBatis-Plus + MySQL(OceanBase) + Redis + MinIO + Elasticsearch + Nacos + RocketMQ
> 服务端口：`8084`（管理端口 `19999`），应用名 `RPBS`

## 1. 系统概述

RMPF（Requirement Management Platform）是面向业务人员与产品经理的**需求全生命周期管理平台**。核心能力：

1. **AI 辅助 BRD/PRD 撰写**：通过外部 Harness AI 平台创建会话、生成业务需求说明书（BRD）与产品需求说明书（PRD）；
2. **任务派发与审批流转**：需求按点派发给产品经理，支持承接/拒绝/撤回/转派/提交审核/业务审批；
3. **工作空间与成员管理**：以"项目/工作空间"为协作单元，管理成员上下文访问权限；
4. **文档版本管理**：BRD/PRD 文件上传至 MinIO，版本记录落库（`bs_document`）；
5. **功能拆解**：PRD 完成后进行业务功能拆解、应用级（前端/后台）技术拆解与同步状态跟踪；
6. **周边能力**：待办（TODO 网关）、消息通知、操作日志、资产点击统计、相似性推荐、主题活动/领域/系统元数据查询。

### 1.1 核心业务流程

```
业务发起需求 → Harness 创建 BRD 会话（AI 扩充书面化）→ BRD 完成
    ↓
按点派发给一个或多个产品经理（每个点 = 一个任务 BsTask）
    ↓
产品经理：承接 / 拒绝(填理由)        ← 承接前业务可撤回任务并改 BRD 重新派发
    ↓ (承接)
自动创建 PRD 工作空间 + Harness PRD 会话（引用 BRD 会话作为 source）
    ↓
PRD 完成 → 提交审核（状态: 待审核）
    ↓
业务发起人（= 需求 initiator）审核：通过 / 拒绝(填理由)
    ↓ (通过)
任务完成 → 指定拆解承接人 → 任务拆解待办 → 批量回调 → 主流程结束
（需求下所有任务均完成时，需求状态自动置为 COMPLETED）
```

### 1.2 关键状态机

**需求状态 `RmpfStatusEnum`（bs_requirement.status）**

| 码值 | 枚举 | 含义 |
|---|---|---|
| 0 | PENDING | 待处理（刚创建） |
| 1 | PROCESSING | 处理中（已派发） |
| 2 | COMPLETED | 已完成（全部任务审核通过，自动流转） |
| 3 | CANCELLED | 已取消 |

**任务状态 `TaskStatusEnum`（bs_task.status）**

| 码值 | 枚举 | 含义 |
|---|---|---|
| 0 | PENDING_ACCEPT | 待承接 |
| 1 | PROCESSING | 处理中（已承接） |
| 2 | REJECTED | 已拒绝（PM 拒绝，validFlag=0） |
| 3 | WITHDRAWN | 已撤回（业务撤回，validFlag=0） |
| 4 | COMPLETED | 审核完成（业务审批通过） |
| 5 | PENDING_REVIEW | 待审核（PM 提交审核） |
| 6 | BUSINESS_REJECTED | 业务已拒绝（可优化后重新提交审核） |
| 7 | DECOMPOSING | 拆解中 |
| 8 | DECOMPOSE_COMPLETED | 拆解完成 |

## 2. 工程结构

### 2.1 Maven 模块划分

```
pom.xml (dapr-apbm-subsys, packaging=pom)
├── rmpf/                      # 启动模块，产出可执行 JAR（rmpf.jar，mainClass=com.hzbank.rmpf.RmpfApplication）
├── rmpf-api/                  # API 契约层：Input/Output DTO、Service 接口
├── rmpf-common/               # 公共层：错误码、常量枚举、工具类（MinIO/ES/RelaBizKey）
├── rmpf-domain/               # 领域层：Entity、Mapper 接口、XML、domain service
├── rmpf-server/               # 服务实现层：Controller、ServiceImpl、拦截器、定时任务
├── rmpf-apbm-common/          # APBM 基础模块（mapstruct）
├── rmpf-apbm-dependencies/    # BOM 依赖管理
├── rmpf-apbm-auth-module/     # 认证授权（7 子模块: pojo/dao/service/api/biz/web/common）
├── rmpf-apbm-conf-module/     # 平台配置（7 子模块）
├── rmpf-apbm-jobm-module/     # 作业管理（7 子模块）
└── rmpf-workflow/             # 【已废弃】Camunda 工作流残留目录，无 pom/src，不参与构建
```

依赖方向：`rmpf → rmpf-server → rmpf-domain → rmpf-api`，`rmpf-server → rmpf-apbm-auth-service`（用户查询）。

### 2.2 分层架构

```
HTTP 请求
   │
   ▼
AuthInterceptor (校验 x-access-token，JWT+Redis)  ──► UserContext (ThreadLocal<BsLoginDTO>)
   │
   ▼
Controller (rmpf-server/controller, 统一返回 Result<T>)
   │
   ▼
Service 接口 (rmpf-server/service) ──► ServiceImpl (@Transactional)
   │            │
   │            ├──► Component/Client (ColossusSystemClient 巨像系统 / RestTemplate 直连 Harness、BFAN)
   │            ├──► ToDoService / MessageService (外部待办、消息网关)
   │            └──► OperationLogUtils (写 bs_operation_log)
   ▼
Mapper (MyBatis-Plus BaseMapper + XML 自定义 SQL)  ──► MySQL(rmpf_db)
```

说明：
- **无 Spring Event 体系**，跨步骤"事件"通过 ① 外部网关调用（待办 ACTION02/ACTION11、消息 MESS0001）② `TransactionSynchronization.afterCommit()` 事务后回调（如 `TaskServiceImpl:1661`）实现；
- **无 Feign**，对外 HTTP 调用走 `RestTemplate`（`gatewayRestTemplate` Bean）+ `HzbHttpClient` 封装；
- 当前用户信息一律从登录态获取：`UserContext.getCurrentSSONo()/getCurrentRealname()/getCurrentUsername()`（等价于 `CurrentUserUtil`，禁止前端传用户 ID）。

## 4. 数据模型设计

### 4.1 ER 概览

```
bs_workspace (工作空间/项目)
   │ 1:N
   ▼
bs_requirement (需求) ◄── N:M ──► bs_requirement_domain_rel (需求-领域)
   │ 1:N
   ├──► bs_document (BRD/PRD 文档版本, doc_type=BRD/PRD, version_no 递增)
   │
   │ 1:N
   ▼
bs_task (任务, parent_task_id 支持子任务树)
   │  ├─ N:M ─► bs_task_domain_rel (任务-领域)
   │  ├─ N:M ─► bs_task_activity_rel (任务-主题活动)
   │  ├─ 1:N ─► bs_app_function_rel (应用级技术拆解) / hs_app_function_rel (历史)
   │  ├─ 1:N ─► bs_function (业务功能) / bs_non_function (非功能需求)
   │  └─ 1:N ─► doc_comment_annotation ── 1:N ──► doc_comment_reply (文档批注)
   │
   └─► bs_operation_log (操作日志, requirement_id + task_id 双维度)
bs_asset_click_log ──汇总──► bs_asset_click_summary
独立配置表: bs_topic_activity, pm_arch_sys, pm_arch_domain_sys_relation, deal_temp(待办临时)
```

| current_brd_doc_version_id | varchar | 当前生效 BRD 版本号（派发存档） |
| status | char | 见 RmpfStatusEnum |
| valid_flag | int | 1 有效 / 0 软删除 |
| created_by/time, updated_by/update_time | - | 审计字段 |

#### bs_task（任务表，统一表达根任务/子任务）

| 字段 | 类型 | 说明 |
|---|---|---|
| task_id | varchar PK | 任务 ID |
| requirement_id | varchar | 所属需求 |
| workspace_id | varchar | 工作空间 |
| parent_task_id | varchar | 父任务 ID（子任务树） |

| valid_flag | int | 拒绝/撤回后置 0 |
| biz_rejected_reason | varchar(512) | 业务拒绝原因 |
| pm_rejected_reason | varchar(512) | PM 拒绝原因 |
| pm_transfer_reason / withdrawn_reason / decompose_transfer_reason | varchar | 各类流转原因 |
| accepted_time / submitted_time / reviewed_time / transferred_time / closed_time | datetime | 各阶段时间戳 |
| callback_flag | int | 拆解完成回调标志（0/1） |
| decomposer_id / decomposer_name | varchar | 任务拆解承接人（审核通过时=原承接人） |
| sys_code / sys_name | varchar | 关联系统 |

#### bs_document（文档版本表，统一管理 BRD/PRD）

| 字段 | 说明 |
|---|---|
| doc_version_id PK | 文档记录主键 |
| requirement_id / task_id | BRD 只挂需求；PRD 挂任务 |
| doc_type | BRD / PRD |
| version_no | 业务版本号，从 1 递增 |
| file_name / file_url / object_name | MinIO 对象定位 |
| file_sha256 | 内容摘要（防篡改/去重） |
| source_workspace_id / source_session_id | 来源 Harness 会话 |
| uploaded_by / remark / 审计字段 | - |

#### bs_workspace（工作空间）

workspace_id(AUTO)、workspace_name、description、owner_user_id/name、valid_flag、审计字段。成员关系由 `bs_workspace_member`（project_space.sql）维护，`WorkspaceContextService.requireMember()` 做成员校验、`canEditContext()` 做编辑权限判断。

#### 其他表

- **bs_function**：业务功能（function_id、requirement_id、task_id、topic_activity_id、function_content、file_id、approval_id/name 对接雪狼立项、project_id）；
- **bs_non_function**：非功能性需求（JSON 内容，file_id 关联 PRD 版本）;
- **bs_app_function_rel / hs_app_function_rel**：应用级拆解（technical_id+title+function_id+app_code+app_type 联合主键；business_rule、acceptance_scene、process_logic、ui_interaction、sync_status 0待确认~4已上线）；
- **doc_comment_annotation / doc_comment_reply**：文档批注及回复（status 1待处理/2已解决/3已关闭，deleted_flag 软删）；
- **bs_operation_log**：operation_type + before_json/after_json 快照；
- **bs_topic_activity**：主题活动配置（编号=拼音首字母，pinyin4j 生成）；
- **pm_arch_sys / pm_arch_domain_sys_relation**：系统/领域元数据（巨像同步落地）；
- **bs_asset_click_log / bs_asset_click_summary**：资产点击明细与日汇总；
- **deal_temp**：待办推送临时表（task_id、rela_biz_key、push_status、todo_type）。

SQL 脚本位置：`rmpf-server/src/main/resources/db/*.sql`、`rmpf-apbm-common/src/main/resources/ddl|dml/*.sql`。

## 5. 接口设计（REST）

统一约定：前缀 `/rmpf/**`（免鉴权白名单 `/rmpf/public/**`）；入参 JSON Body 或 Path Variable；返回 `Result<T>`；鉴权 Header `x-access-token`。

### 5.1 需求域 `RequirementController` (`/rmpf/requirement`)

| 方法 | 路径 | 入参 | 职责 |
|---|---|---|---|
| POST | `/add` | RequirementAddInput | 新增需求：校验→建 Harness BRD 会话→落库→记日志，返回 requirementId/brdSessionId/accessToken/directory |
| POST | `/updateDomain` | RequirementUpdateDomainInput | 修改需求业务领域（全删全增 rel 表），限未完成状态 |
| POST | `/updateTitle` | RequirementUpdateTitleInput | 修改需求标题 |
| POST | `/dispatch` | RequirementDispatchInput | 需求派发（核心，见 §6.1） |
| DELETE | `/{id}` | - | 删除需求（软删；存在进行中任务则禁止） |
| POST | `/transfer` | RequirementTransferInput | 需求跨工作空间转移（连带任务） |
| GET | `/querySystemInfo` | - | 查询可选系统列表 |

### 5.2 任务域 `TaskController` (`/rmpf/task`)

| 方法 | 路径 | 职责 |
|---|---|---|
| POST | `/reject` | PM 拒绝任务（须待承接，须本人，填理由≤512） |
| POST | `/withdraw` | 业务撤回任务（须待承接，限派发人/发起人） |
| POST | `/transfer` | 任务转派（更换承接人，记 transfer_reason） |
| POST | `/accept` | PM 承接（自动创建 PRD 工作空间+Harness 会话，乐观锁更新） |
| POST | `/updateTitle` | 修改任务标题（≤25 字符，仅派发人，限待承接/处理中） |
| POST | `/submitReview` | 提交审核（处理中/业务已拒绝 → 待审核，建审核待办） |
| POST | `/businessReject` | 业务审核拒绝（须发起人，状态→业务已拒绝，通知 PM） |
| POST | `/businessApprove` | 业务审核通过（状态→已完成，指派拆解人，检查需求整体完成度） |
| POST | `/queryApprovedList` | 已审批任务分页列表 |
| POST | `/batchCallback` | 拆解完成批量回调（callbackFlag=1） |
| POST | `/cocreate` | 协同创建子任务 |
| POST | `/queryTask` / `/queryToDoTasks` | 任务查询 / 我的待办任务 |
| POST | `/notifyDecomposeStatus` / `/queryDecomposeStatus` / `/queryDecomposeTasks` | 拆解状态通知/查询 |
| POST | `/decomposeTransfer` | 拆解任务转派 |

### 5.3 功能拆解域

- `AppFunctionController` (`/rmpf/appFunction`)：`batchSave` 批量保存拆解、`dismantled` 触发拆解、`taskTechnical` 技术功能点查询、`queryDismantledDetail` / `queryModuleDismantled` 详情、`queryHistory` 历史记录、`downloadDismantledResult` 结果下载；
- `FunctionInfoController` (`/rmpf/function`)：`save`（保存 PRD 功能并异步拆分章节入库，正则 FUN\d+）、`query`；

- `PublicController` (`/rmpf/public`，免鉴权，供 AI/Harness 侧回调)：`function/queryFunctionList`、`function/detail`、`function/callback/update`、`appFunction/pageQuery`、`appFunction/update`。

### 5.4 Harness AI 集成 `HarnessController` (`/rmpf/harness`)

| 路径 | 职责 |
|---|---|
| POST `/breakdown/open` | 打开个人拆解入口（openPersonalBreakdown） |
| POST `/token/refresh` | 刷新 Harness accessToken（Redis 存取 SsoNo-Token 映射） |

`HarnessSessionServiceImpl`（868 行）直连 Harness 开放 API：

| 常量 API | 用途 |
|---|---|
| `/api/open/users/upsert` | 同步用户到 Harness |
| `/api/open/token/exchange` | Token 换取 |
| `/api/workspace/provision` | 开通工作空间 |
| `/api/harness/ocse/im/session/group/createByTeam` | 按团队创建会话组 |
| `/api/harness/harnessSession/{sessionId}/message` | 发送会话消息 |

场景码：BRD=`scene_requirement_brd`/`requirement_brd`，PRD=`scene_requirement_prd`/`requirement_prd`。PRD 会话以 `{brdSessionId}:brd` 作为 sourceBrdRoomId 引用 BRD 上下文，并通过 runVariables 注入 rqrmProjectId、systemCode/Name、assigneeUserId/Name（author 默认同 assignee）等变量，随后发送 bootstrap 引导消息。

## 6. 核心流程详细设计

### 6.1 需求派发 `RequirementServiceImpl.dispatch` (:528, @Transactional)

1. 参数校验：requirementId、currentBrdDocVersionId、taskList 非空；逐项校验 taskName、assigneeUserId、systemCode/Name、domainCode/Name；
2. 取当前用户为派发人；查需求并校验 validFlag=1、workspaceId 非空；
3. 查最新 BRD 版本（`bsDocumentService.getLatestBrdDocument`），**必须等于入参版本**（保证基于最新 BRD 派发）；
4. 批量查 PM 用户（`bsUserService.batchQueryUserBySsoNo`）补全姓名，缺失则报错；
5. 保存需求-领域关联（去重后全删全增）；
6. 逐条处理任务：
   - 带 taskId → **复用**已拒绝/已撤回任务：校验归属与状态，恢复 validFlag=1、status=0，清空拒绝/撤回原因与 closedTime；
   - 不带 taskId → **新建**任务（status=0 待承接、callbackFlag=0）；
   - 均保存任务-领域关联 + 记 TASK_CREATE 操作日志；
7. 回写需求存档版本、更新 updateTime；
8. `workspaceContextService.addWorkflowMembers` 将全体承接人加入工作空间成员（与派发同事务）；
9. **批量创建派发待办**（一次网关调用多条 insertActionInfoInputDetail，失败仅告警不阻断）；
10. 需求状态 0→1（PROCESSING）；
11. 返回每条任务的派发结果（含 reused 标记）。

### 6.2 任务承接 `TaskServiceImpl.accept` (:659, @Transactional)

1. 校验 taskId；查任务；状态必须=0 待承接；
2. 权限：当前用户必须=assigneeUserId；
3. `createPrdWorkspace(:801)`：查需求 → sourceBrdRoomId=`{brdSessionId}:brd` → 组装 runVariables → `harnessSessionService.createPrdSession` → 成功后 `sendPrdBootstrapMessage` 发送引导消息；失败抛 RMPF0062；
4. 乐观锁更新：`UPDATE ... WHERE task_id=? AND status='0'`，影响行数≠1 视为并发冲突抛异常；写入 status=1、acceptedTime、prdWorkspaceId/prdSessionId；
5. 创建消息通知派发人（MSG_SMALL_CLASS_TASK_DISPATCH）；
6. 更新派发待办为已完成（behavStatus=1）；
7. 记 TASK_ACCEPT 操作日志。

### 6.3 提交审核与业务审批

- `submitReview` (:1158)：状态∈{1 处理中, 6 业务已拒绝} → 5 待审核，记 submittedTime，建审核待办（派发人为审核人）；
- `businessReject` (:1296)：状态必须=5；**权限=需求发起人**（非派发人）；状态→6，记 bizRejectedReason/reviewedTime，消息通知 PM，审核待办置"拒绝"；
- `businessApprove` (:1457)：状态必须=5；权限=发起人；状态→4，decomposerId/Name=原承接人，`addWorkflowMembers` 补成员；**检查该需求下全部有效任务是否均为 4**，是则需求状态自动→2 COMPLETED 并记日志；审核待办置完成，并为拆解人创建拆解待办。

### 6.4 拒绝/撤回/转派

- `reject` (:193)：状态必须=0，当前用户=承接人，理由≤512；乐观锁置 2 + validFlag=0 + closedTime；通知派发人；
- `withdraw` (:333)：派发人在 PM 承接前撤回，置 3 + validFlag=0，可改 BRD 后重新派发（复用 taskId）；
- `transfer` (:458)：更换承接人，记 pmTransferReason/transferredTime，待办移交（`transferTodoExecutor` 线程池异步）。

### 6.5 PRD 功能拆分（异步）

`FunctionInfoServiceImpl.save` → 解析 PRD 功能内容 → `splitTaskExecutor` 线程池异步执行 `splitPrdDocumentAndSave`（章节正则 CHAPTER_REGEX，默认 6 章）/ `splitNonFunctionChapter` → 写 `bs_function` / `bs_non_function`；功能编码正则 `FUN\d+`。

### 6.6 应用级拆解

`AppFunctionServiceImpl.dismantled` → `dismantledTaskExecutor` 异步拆解 → 写 `bs_app_function_rel`（联合主键 technicalId+title+functionId+appCode+appType），appType∈{fronted, backend}，syncStatus 0→4 全链路跟踪；`hs_app_function_rel` 存每次拆解历史；`batchCallback` 批量回调置 callbackFlag=1。

### 6.7 定时任务（天枢 SchedulerX，BasicProcessor）

| Job | 作用 |
|---|---|
| AssetClickStatsJob | 点击明细 → 日汇总（statDate+assetId 幂等） |
| DomainAndSysTask | 巨像领域/系统元数据同步落地 pm_arch_* |
| SplitPrdDocumentTask | PRD 文档章节补偿拆分 |

## 7. 横切设计

### 7.1 认证与用户上下文

`WebMvcConfig` 注册 `AuthInterceptor` 拦截 `/rmpf/**`、`/auth/**`（排除 `/rmpf/public/**` 与登录接口）：读取 `x-access-token` → `BsLoginService`（APBM auth 模块，JWT + Redis 会话）校验 → 写入 `UserContext`（`ThreadLocal<BsLoginDTO>`）。Service 层通过 `UserContext.getCurrentSSONo()/getCurrentRealname()/getCurrentUsername()` 取用户；**任何接口都不接受前端传入的用户身份**。

### 7.2 异常与错误码

- 全局异常处理器 `GlobalExceptionHandler` → 统一 `Result.fail`；
- 业务异常 `BizException(RmpfErrorCodeEnum...)`，错误码定义于 `rmpf-common/.../RmpfErrorCodeEnum.java`（RMPF0001~RMPF0113，实现 IExceptionInfo，支持 `{}` 占位符）；
- 典型错误码：RMPF0001 资源不存在、RMPF0005 重复/写入失败、RMPF0007 参数校验（通用）、RMPF0015/16 BRD 版本问题、RMPF0022~24 任务复用校验、RMPF0025~28 拒绝校验、RMPF0039~44 承接/改标题校验、RMPF0048~55 审核校验、RMPF0062 Harness 接入失败。

### 7.3 并发控制

任务状态变更采用**条件乐观锁**：`UpdateWrapper.eq("task_id", ?).eq("status", 前置状态)`，影响行数≠1 抛并发冲突异常；行级锁场景使用 `selectForUpdate`（FOR UPDATE）。

### 7.4 事务边界

Service 方法级 `@Transactional(rollbackFor = Exception.class)`；外部网关调用（待办/消息/Harness）置于事务内但**失败降级为 warn 日志不阻断主流程**；需事务提交后再执行的副作用使用 `TransactionSynchronizationManager.registerSynchronization(... afterCommit())`。

### 7.5 日志规范

- 入口/出口 info（含 input/output 关键字段）；
- 校验失败先 `log.warn` 再抛 BizException；
- 写库失败/外部调用异常 `log.error` 带关键 ID；
- 占位符风格 `log.info("操作描述，key: {}", v)`，禁用字符串拼接。

### 7.6 操作审计

`OperationLogUtils.recordRequirementLog / recordTaskLog` 写 `bs_operation_log`：operation_type（REQUIREMENT_CREATE/ASSIGN/UPDATE/DELETE、TASK_CREATE/ACCEPT/REJECT/WITHDRAW/TRANSFER/UPDATE/SUBMIT_REVIEW/BUSINESS_REJECT/BUSINESS_APPROVE）+ 前后 JSON 快照。

### 7.7 外部系统集成清单

| 目标系统 | 方式 | 用途 |
|---|---|---|
| Harness AI 平台 | RestTemplate 直连（HARNESS_GATEWAY + CHANNEL_SECRET） | BRD/PRD 会话、用户同步、Token、消息 |
| TODO 待办网关 | 网关交易码 ACTION02 创建 / ACTION11 更新 / ACTION65 查询 | 派发/审核/拆解待办 |
