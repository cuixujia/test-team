# 需求文档质检规范

## 质检目的与深度

用户选定范围后，只质检目标功能、相关依赖和明确的全局约束，不深度检查无关功能。目的不是把 PRD 检查到可直接编写全部 TC，而是确认已选范围足以生成**有依据、范围清楚、结果可判定的业务级 TP**。

保留五维检查，但**只把会影响 TP 归组、拆分或通过判定的问题**列为问题。不影响 TP 生成与判定的 TC 级细节（字段枚举、页面文案、接口错误码等）**不进问题清单、不登记、不向用户展示**。

## 五维检查

| 维度 | 必查：影响 TP 的内容 | 不属于本阶段检查范围 |
|---|---|---|
| **完整性** | 业务目标、功能范围、参与角色、关键前置条件、结果方向；会改变结果的主要分支；明确的排除项与外部依赖 | 全量测试数据、字段取值枚举、详细边界值、页面文案和布局、接口字段与错误码 |
| **一致性** | 目标功能与关联流程、跨模块规则之间是否冲突；状态、角色、业务对象等关键术语是否同义 | 不影响目标功能行为的文字、格式和非关键命名问题 |
| **无二义性** | 歧义是否会改变业务目标归属、TP 是否拆分、角色/状态处理或通过标准 | 不改变上述内容的展示和实现细节 |
| **可测试性** | 每项业务能力是否有可观察的结果方向，能否判断通过或不通过；是否依赖无法确认的外部条件 | 具体造数方案、字段级组合、精确提示文案；PRD 未给出的性能数值不得自行补写 |
| **可追溯性** | 每项 TP 是否能定位到 PRD 原文（文件:行号）或澄清编号；目标范围和排除范围是否可区分 | 与本次目标功能无关的全篇修订历史整理 |

## 矛盾检测

一致性维度**不得凭印象自由检索**。先依据「资料角色登记」和 outline.md 筛出所选功能章节、全局规则及跨功能引用（主资料优先、辅资料仅交叉印证），再按种子词表检索这些相关片段并做语义比对；不扩展检查无关功能。结论（兼容/冲突/无法判定）留痕。冲突按 `prd-record-spec` 二节：**主资料有言、辅资料相悖且影响 TP 判定才登记**；不影响 TP 生成与判定的矛盾只留痕。

| 维度 | 种子词表示例 | 比对目标 |
|---|---|---|
| 数据可见范围 | 可见/权限/范围/自己创建/项目归属/创建人 | 同一对象的可见判定规则是否唯一 |
| 操作入口与按钮归属 | 按钮/入口/操作区/编辑/复制/删除/只读/无修改 | 目标功能与他功能对同一页面的入口描述是否兼容 |
| 状态流转 | 状态/待审核/已审核/关闭 | 状态枚举与流转规则是否唯一 |
| 角色能力 | 角色/测试人员/测试管理人/管理员/可配置 | 角色与能力分配规则是否唯一 |
| 字段与统计标准 | 字段/取值/统计/来源 | 同一字段的取值来源与统计规则是否唯一 |
| 时间与触发条件 | 触发/定时/实时/当天/时间 | 触发时机与时间标准是否唯一 |
| 校验时机 | 校验/身份/前置/阻止/拦截/权限 | 同一行为的校验时机与条件在各处描述是否唯一 |

> **检索交给工具，判读交给 LLM。** 种子词表是本 skill 的静态资产，逐次迭代积累。
> **同类横向自查**：对同属一个页面/同一交互层级的候选（如分页与排序）做处置一致性核对；判定不一致时必须写明实质差异，否则同判。

## 防误报判据

### 有意决策判据（三问全满足则不登记）

对「PRD 未给出量化标准/细节」的候选问题：

1. PRD 是否明确声明不设硬性指标或有意留白？
2. PRD 是否给出了验证方式（哪怕主观走查或方向性约束）？
3. 该缺失是否不影响业务级 TP 的归组、拆分或通过判定？

三问不满足、属真缺失且影响 TP 判定的，正常登记。

### 登记前最后一问（收口）

每个候选登记前强制回答：**该问题是否会产生两种互斥的预期结果，或改变某 TP 的归组、拆分、通过判定？**

- 是 → 登记
- 否 → 不登记

**「输入不全类」判别模板**：PRD 写出某能力（如列表「支持部分列排序」「分页展示」）但未给出枚举、清单或参数时，默认属 TC 级细节，不登记；仅当该能力整体无任何判定依据（结果方向完全不可判）时才登记。

### 待核验标记消歧

PRD 的「待核验/待澄清」标记只吸收该条目**自身未定**的部分；已写死内容之间的冲突——即在任何待核验结论下都存在的矛盾——**不得被标记吸收，必须登记**。

## 引文与范围复核

**保真的裁决权在脚本**——每条原文摘录（`文件:行号「原话」`）由 `scripts/verify_quotes.py` 对原文件逐字机验，**报告不逐条人工复核字面**；你的复核精力只投在第 2、3 项及机验测不了的断章风险。复核项：

1. **保真（机验）**：`verify_quotes.py` 全量跑通（规则出处：`prd-record-spec`，此处仅引用不重复定义）；质检专家不重复跑，引用脚本退出码即可。
2. **断章定向抽查**：抽验 **≥5 条**，必须覆盖**权限、状态流转、边界值**三类最易断章的规则；用 `--context` 打印的上下文核对摘录是否偏离原意，结论写入报告附录。
3. **范围一致**：需求基线只覆盖用户选定的功能及明确批准的依赖，不越界预建；每条已确认需求必须有直引证据（`文件:行号「原话」`）或澄清证据。

疑似断章或范围外项列为需用户确认的问题，由经理在澄清环节一并确认。

## 问题分级

问题清单只收录影响 TP 生成与判定的问题，仅两级：

- **Blocker**：目标业务能力或通过标准无法确定，无法生成可判定的 TP
- **Major**：可以形成暂定 TP，但未决问题可能改变 TP 范围、拆分或验收结果

## 报告模板

```markdown
# <目标功能> 测试点资料质检报告

## 结论
Blocker: N 项 / Major: N 项
是否可进入阶段 5：是 / 否（原因）

## 问题清单
| 问题编号 | 维度 | 证据位置 | 问题描述 | 级别 | 改进建议 | 对测试的影响 |
|---|---|---|---|---|---|---|

## 处置记录
| 日期 | 问题编号 | 用户处置（已修复/已补充/拒绝并降级） | 备注 |
|---|---|---|---|

## 附录：候选判定留痕
| 候选 | 处置（登记/不登记） | 一行理由 |
|---|---|---|

## 附录：引文抽查复核
| 摘录（文件:行号） | 断章风险判定 | 说明 |
|---|---|---|

## 附录：矛盾检测留痕
| 维度 | 种子词 | 命中位置 | 比对结论（兼容/冲突/无法判定） | 说明 |
|---|---|---|---|---|
```

> **挑战位**：若您发现本报告未列出的疑似矛盾或缺失，请直接提出，我将按判据核实后补充登记或说明不登记理由。

## 措辞要求

「问题描述」「对测试的影响」两列按「现状（哪里写了什么）→ 差异/缺失 → 影响」直白句式，一句话说清。

- 正例：「两条规则说法不一致：一条说按项目归属判断可见范围，另一条说普通测试人员只能看自己创建的风险」
- 反例：「两条规则存在口径张力」

## 澄清与处置

1. 用户澄清/补充说明后：核对受影响问题，更新处置记录。澄清结论由测试经理以 `CL-<序号>` 编号登记于澄清记录；后续报告与派发单仅引用 CL 编号 + 关键句，不贴全文。
2. 资料变更：**以 `files-manifest.md`（Python 口径 sha256）与需求基线 `input_files` 指纹为基准比对**，无指纹或指纹不符即暂停重评，请用户二选一（恢复原资料 / 该功能从入库重新开始）。
3. Blocker 未清零：声明风险 → 用户二次确认 → 状态档案登记降级决策。
