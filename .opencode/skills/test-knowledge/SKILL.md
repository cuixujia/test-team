# 测试知识库（唯一权威知识源）

本 skill 不定义任何规则本身，只登记知识清单、阅读路径和维护规则。**所有测试语义判定的最终依据在这里，其它 skill 只能引用、不得复述。**

## 一、知识清单

路径锚点：附属知识件以 skill 自身目录为准——本地开发环境为 `.opencode/skills/test-knowledge/references/`；服务端全局安装为 `~/.config/opencode/skills/test-knowledge/references/`，二者同构。前四份为**原文只读件**，一字不改：

| 文件 | 解决什么问题 | 关键章节 |
|---|---|---|
| `references/1 通用测试方法论.md` | 用什么方法测 | §5 方法详解、§7 方法选型决策指南 |
| `references/2 测试维度定义.md` | 从哪些维度测 | §二 维度明细、§三 维度选型指南（银行场景→维度组合） |
| `references/3 通用测试规则.md` | 每个维度具体测什么 | §一 功能测试（1~6 维度逐项关注点）、§二 非功能测试、附录对应关系 |
| `references/4 测试点生成指南.md` | 测试点怎么拆、怎么命名、怎么从需求推导 | §二 功能点拆分、§三 命名规范、§四 颗粒度、§五 模板库、§六 生成工作流程 |

补充件可增改；前四份原文不可变——需要修订知识原文时，由用户决定整体替换文件。

## 三、维护规则

1. 原文四份为生效知识，行文中的流程/输出包装已按「知识聚焦」原则删除（2026-11-05 整改：Agent 工序句、产物形态约束、交接动作句、目录断头项）；此后原文不再改动，调优只动**补充件**，或经用户决定整体替换原文。仓库根 `测试知识/` 为**导入原始存档**（保留原貌），两者不再要求字节一致。
2. 原文内保留的「工作流程/步骤」表述一律按**判定方法**理解；工序交接与产物形态（清单/报告/命令）以 skill 层契约为准（`prd-record-spec`、`test-point-spec`、派发单）。
3. 其它 skill 与本文档口径不一致时，**以本文档为准**：改 skill 的复述为引用，不改知识。
4. 新增知识或补充件时，在本文件「知识清单」表登记一行；新写句子入「知识」的门槛=可脱离阶段/产物独立成立；删除条目前先检查无 skill 引用。
