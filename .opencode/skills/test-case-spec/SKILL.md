# 测试用例（TC）规范

## 定义

**测试用例（TC）= 一条含完整执行信息（前置条件、测试数据、操作步骤、预期结果）的可执行验证，一条用例只验证一个目的。**

- 可执行：执行者无需追问即可照做
- 与 TP 的关系：TC 必须且只能关联一个 TP；一个 TP 至少派生一条 TC

## 字段规范

| 字段 | 要求 |
|---|---|
| 编号 | `TC-NNN`，三位序号，本次任务内连续，只增不改不复用；**不含业务功能编号** |
| 标题 | 「场景 + 预期」结构，如「金额超单笔限额，交易拒绝并提示」 |
| 关联TP | 单个 TP 编号（一对一关联，禁止多值） |
| 优先级 | P0 核心主流程 / P1 重要分支与边界 / P2 次要场景 / P3 罕见与健壮性 |
| 前置条件 | 可构造的具体状态（账户、数据、权限），禁止「系统正常」类空话；环境/版本要求属前置条件，不单列字段 |
| 测试数据 | 具体值或可执行构造方法，金额/字段给到具体数值 |
| 操作步骤 | 操作者视角，动词开头，编号分步，无歧义词 |
| 预期结果 | 可观察、可判定的结果（界面提示/账务变动/响应码/数据落库），多结果分点列出 |
| 用例类型 | 正向 / 反向 / 边界 / 异常 / 流程（归类判据见质量标准） |
| 标签 | 归属标记，**可含多个标签值**，格式见下文「标签规范」 |

## 质量标准

- **一个 pass/fail 结论**：验证「金额超限拒绝」的用例不得同时断言手续费计算；预期结果可有多个观察点（如「余额不变 + 流水生成」），但必须同属一次判定，出现第二种判定即拆分。
- **用例类型归类判据**：边界 = 取值在分区边缘（恰等于/恰超出）；异常 = 系统或环境故障（超时/断网/脏数据）；反向 = 操作者合法但违反业务规则被拒；流程 = 跨页面/跨系统的多步骤业务旅程；正向 = 其余正常场景。交叉时按 **边界 > 异常 > 反向 > 流程 > 正向** 取第一个命中（正向兜底）。
- **步骤可执行性判据**：步骤含具体入口、输入值、操作对象；不含「等一下」「适当输入」。
- **预期可判定判据**：预期结果有具体值/文案/状态，可直接判 pass/fail。
- **前置条件与测试数据分离**：前置是状态，数据是输入。

## 标签规范

标签列表达用例的归属，**可含多个标签值**，格式为分号分隔的 `键：值` 组合：

```text
所属系统：星云风险管理系统；所属业务活动：风险管理；所属业务功能：新增风险
```

| 标签 | 取值来源（必须来自 PRD 真实内容） | PRD 中确实没有时 |
|---|---|---|
| 所属系统 | PRD 封面、文档头或项目文档中的系统名称 | **留空**（不写「无」「待定」「N/A」） |
| 所属业务活动 | PRD「**模块划分说明**」中的**模块名称**；该节不存在时，取 PRD 正文中真实出现的模块分组 | **留空** |
| 所属业务功能 | PRD「**功能矩阵总表**」中的**功能名称**；该表不存在时，取 PRD 正文中真实出现的功能名称 | **留空** |

**留空判定**：只有在 PRD 全文中**确实检索不到**该类信息时才允许留空。不得因整理麻烦而留空，也不得为填满而编造名称。

**取值要求**：

- 与 PRD 原文**逐字一致**，禁止缩写、改写、自造同义词。
- 同一标签只出现一次，值为该用例所属的那一项；一条用例只属于一个业务功能、一个业务活动、一个系统。
- 标签中写的是**名称原文**，**不是业务功能编号**（业务功能编号不进入最终产物）。

## 清单模板

```markdown
# <目标功能> 测试用例清单（状态：草稿 / 质检后 / 已评审）

| 编号 | 标题 | 关联TP | 优先级 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 用例类型 | 标签 |
|---|---|---|---|---|---|---|---|---|---|

## 覆盖对照表（测试点→用例）
| TP编号 | 覆盖的 TC 编号 | 未覆盖原因 |
|---|---|---|
（未覆盖项必须显式填写原因，禁止留空）
```

> **列序为校验契约**，`scripts/verify_test_cases.py` 按此解析，禁止调整。

## 输入与历史测试用例使用规则

阶段 10 的输入以派发单与阶段 8 资料质检报告为准：

- **必须** = 阶段 7 已验收的测试点清单 + 测试点生成资料包（PRD 原文、锚点底册、任务功能清单、澄清记录）+ 开发设计文档（前端/后端）。
- **可选** = 数据库设计文档、存量测试用例；不存在或为空时标注「未提供」并跳过，**存在但不可读时不得静默跳过**，应移交经理处理。
- 可选资料与 PRD 冲突时以 PRD 为准；可能改变 TC 范围或判定的冲突交经理请用户澄清。

**存量测试用例仅作场景与步骤写法参考**：禁止照抄历史编号与标题；每条 TC 仍须满足字段规范、关联本次验收基线的 TP。

## 交付约束

- 最终交付的测试用例清单中**不得出现业务功能编号**——归属信息通过标签列表达。
- 交付前运行 `scripts/verify_test_cases.py`，退出码非 0 时必须修复后重跑。

## 变更规则

- 阶段 12 评审：**用户直接删改的行即刻生效、不回炉复检**（与阶段 7「用户裁决即最终结论」口径一致，经理记录差异到状态档案）；若需设计专家按评审意见继续修订，修订后只对**受影响行**走质检的**增量复检**，终轮全量兜底。
- 设计材料变更或此前缺失的必需资料补齐 → 受影响 TC 标记失效并重生成、走增量复检；未受影响的已确认基线保留。
