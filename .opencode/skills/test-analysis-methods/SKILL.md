# 测试分析方法（衔接层）

> 方法学的唯一权威在知识库 `test-knowledge`：
> - **选什么方法** → 知识①《通用测试方法论》§7 方法选型决策指南（等价类/边界值/判定表/因果图/状态迁移/正交实验/场景法/错误推测/探索性测试）
> - **方法怎么做** → 知识① §5 方法详解
> - **每个维度测什么** → 知识③《通用测试规则》对应维度关注点
> - **银行/Web/接口专项** → `test-knowledge/references/补充-领域检查单.md`
>
> 本 skill 不复述方法学，只登记两件团队衔接规则：方法产出如何分配到 TP/TC，以及发散-收敛工作法。

## 一、方法产出 → TP/TC 层级衔接（阶段 5 强制）

| 需求形态 | 首选方法（知识①） | 产出分配 |
|---|---|---|
| 输入域（字段取值/格式/长度） | 等价类 | TC 覆盖维度；TP 按所属业务能力收拢 |
| 业务规则组合（多条件判定） | 判定表 | TC 组合场景；只有不同业务目标或明确不同结果才拆 TP |
| 业务流程（多角色/多步骤） | 场景法 | 基本流、备选流和异常流的 TC 场景；按业务目标和规则决定 TP |
| 状态流转（账户/订单生命周期） | 状态迁移 | TC 覆盖状态与迁移；TP 不按每个状态或迁移逐条拆分 |
| 参数组合爆炸（配置项多） | 正交实验 | TC 参数组合；TP 按业务能力收拢 |
| 历史缺陷/风险经验 | 错误推测 | 受 PRD 支持的风险覆盖维度；不得仅凭经验新增 TP |

总口径：**用方法铺开场景与数据归 TC，用业务目标与切分规则收敛成 TP**；TP 的「分析方法」列填写用于识别该业务目标的方法名（枚举见 `test-point-spec`）。

## 二、发散-收敛工作法（阶段 5 强制）

1. **发散**：对每个需求条目，按知识②的维度组合和上述方法列出覆盖维度和场景（输入类别、边界、角色、流程分支、状态迁移、参数组合）；此时**不**把每个维度或场景写成一条 TP。
2. **收敛**：按知识④§四和 `test-knowledge/references/补充-TP切分与命名判别.md` 先确定业务验证目标，再合并同一业务能力下的并列条件与同规则下的不同数据/对象/角色；将具体覆盖维度和场景留给 TC；剔除无依据项并映射到证据（规则见 `prd-record-spec`）。
