# 测试分析方法（衔接层）

> 方法学的唯一权威在知识库 `test-knowledge`：
> - **选什么方法** → 知识①《通用测试方法论》§7 方法选型决策指南（等价类/边界值/判定表/因果图/状态迁移/正交实验/场景法/错误推测/探索性测试）
> - **方法怎么做** → 知识① §5 方法详解
> - **每个维度测什么** → 知识③《通用测试规则》对应维度关注点
> - **银行/Web/接口专项** → `test-knowledge/references/补充-领域检查单.md`
>
> 本 skill 不复述方法学，只登记团队衔接规则：方法产出如何分配到 TP/TC。

## 一、方法产出 → TP/TC 层级衔接（阶段 5 强制）

> 层级总口径以 `补充-TP切分与命名判别.md` 裁决十为准：**测试小类落在 TP 层**，方法产出的数据与场景落在 TC 层。

| 需求形态 | 首选方法（知识①） | 产出分配 |
|---|---|---|
| 输入域（字段取值/格式/长度） | 等价类 | 命中「字段校验」小类 → 出该小类 TP；各等价类与边界取值由该 TP 下多条 TC 覆盖 |
| 业务规则组合（多条件判定） | 判定表 | 命中「业务规则」小类 → 出该小类 TP；各条件组合由该 TP 下多条 TC 覆盖 |
| 业务流程（多角色/多步骤） | 场景法 | 命中「主流程 / 分支流程 / 状态流转 / 流程衔接与回退」等小类 → 逐项出 TP；基本流、备选流、异常流的场景由各 TP 下 TC 展开 |
| 状态流转（账户/订单生命周期） | 状态迁移 | 命中「状态流转」小类 → 出该小类 TP；各状态与迁移由该 TP 下 TC 覆盖，TP 不按每个状态逐条拆分 |
| 参数组合爆炸（配置项多） | 正交实验 | 命中对应小类 → 出该小类 TP；参数组合由该 TP 下 TC 覆盖 |
| 历史缺陷/风险经验 | 错误推测 | 仅用于 TP 下 TC 的场景补充；不得据此新增 TP（TP 只由资料命中的小类产生） |

总口径：**用资料命中的测试小类确定 TP，用分析方法把每个 TP 的场景与数据铺开成多条 TC**；TP 的「分析方法」列填写用于展开该 TP 的方法名（枚举见 `test-point-spec`）。同一小类内不按字段、输入值、角色、控件拆 TP；不同小类必须拆成不同 TP。
