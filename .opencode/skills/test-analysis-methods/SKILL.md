# 测试分析方法库

## 方法选用矩阵（按需求形态选方法）

| 需求形态 | 首选方法 | 补充方法 | 典型覆盖产出 |
|---|---|---|---|
| 输入域（字段取值/格式/长度） | 等价类 | 边界值 | TC 覆盖维度；TP 按所属业务能力收拢 |
| 业务规则组合（多条件判定） | 判定表 | 因果图 | TC 组合场景；只有不同业务目标或明确不同结果才拆 TP |
| 业务流程（多角色/多步骤） | 场景法 | 错误推测 | 基本流、备选流和异常流的 TC 场景；按业务目标和规则决定 TP |
| 状态流转（账户/订单生命周期） | 状态迁移 | — | TC 覆盖状态与迁移；TP 不按每个状态或迁移逐条拆分 |
| 参数组合爆炸（配置项多） | 正交实验 | — | TC 参数组合；TP 按业务能力收拢 |
| 历史缺陷/风险经验 | 错误推测 | — | 受 PRD 支持的风险覆盖维度；不得仅凭经验新增 TP |

## 各方法要点

- **等价类**：划分有效/无效输入，作为 TC 覆盖维度；同一业务能力下不按等价类数量增加 TP。
- **边界值**：按 min-1/min/min+1、max-1/max/max+1 等选取 TC 数据；边界点本身不各自生成 TP。
- **判定表**：枚举条件组合，形成 TC 场景；仅当 PRD 明确不同业务目标或不同处理结果时拆分 TP。
- **因果图**：把互斥、包含、要求、屏蔽等关系转为 TC 场景；TP 仍按业务能力和明确规则收拢。
- **场景法**：基本流、备选流和异常流用于检查覆盖；不因每条流程分支单独生成 TP。
- **状态迁移**：用 TC 覆盖相关状态和迁移；不按每个状态或迁移单独生成 TP。
- **正交实验**：用 L_n 正交表选择 TC 参数组合；组合数量不决定 TP 数量。
- **错误推测**：依赖经验清单（见下方领域检查单）。

## 发散-收敛工作法（阶段 5 强制）

1. **发散**：对每个需求条目，列出覆盖维度和场景（如输入类别、边界、角色、流程分支、状态迁移、参数组合）；此时**不**把每个维度或场景写成一条 TP。
2. **收敛**：按 `test-point-spec` 先确定业务验证目标，再合并同一业务能力下的并列条件与同规则下的不同数据/对象/角色；仅不同业务目标、主资料明文规定不同流程/规则/权限/结果、主副项不同验收时拆分；将具体覆盖维度和场景留给 TC；剔除无依据项并映射到一个或多个证据（`文件:行号「原话」` 或 `CL-xxx`）。
3. TP 的「分析方法」填写用于识别该业务目标及其覆盖范围的方法；具体场景和数据由 TC 承接。

## 银行业务专项检查单

- **金额**：精度/舍入规则、币种、大额阈限、借贷平衡
- **账务**：幂等（重复提交）、冲正/反交易、日终批量与对账文件
- **权限**：角色隔离、越权访问、敏感数据脱敏与加密
- **合规**：监管报送字段、留痕审计、黑名单校验
- **异常**：超时重试后的状态一致性、部分成功的补偿

## Web 应用专项检查单

- **兼容**：浏览器/分辨率/响应式断点
- **会话**：登录态过期、并发登录、CSRF/XSS 防护
- **交互**：重复点击防抖、表单重置、错误提示可理解性
- **弱网/中断**：提交中断后的数据一致性

## 接口专项检查单

- **参数**：必填/类型/长度/枚举/格式校验
- **契约**：字段增删改的兼容性、必返回字段
- **异常码**：业务错误码全覆盖、错误信息不泄露敏感数据
- **幂等与重试**：重放请求结果一致
- **安全**：签名/加密/时间戳防重放

## 非功能维度（按需启用）

仅当 PRD 明确提及或属高风险场景时启用：性能阈值、安全、兼容性、可靠性；启用时在 TP 类型中标注「非功能」。
